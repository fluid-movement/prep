- `internal/cli/hook.go`, `hookRecordArea(p, cwd, root)`: a relative or empty `p` is joined to `cwd`. With `p == ""` the result is `cwd` itself, so when the shell's working directory is `.prep`, `.prep/issues` or below, the call reports the issue or knowledge area although the command names no path. Return "" for an empty path before joining.
- Callers: `hookArea` (file tools, and each token of a target) and `hookShellArea` in `internal/cli/hook_shell.go` (each Bash segment, from `hookDenial`). Check that no caller passes "" or "." for a command without path arguments, and that a bare `cd ..`, `pwd`, `git status` and `prep check` are allowed from inside `.prep/issues`.
- Relative paths that really point into the records must still redirect from there: `cat issue.md` inside an issue directory, `ls` with an explicit `.` or a directory argument. A bare `ls` with no argument lists record files; allowing it is acceptable, since blocking it is what traps the agent.
- The after-tool hook uses the same `hookArea` for the activity area; an empty target there falls back to code or other, which is correct.
- Seen in practice: a run of about eight denied calls (`echo hi`, `prep check`, `git -C ... status`, `cd ... && pwd`) in one fpa-events session ([finding](/findings/01M72A9TBJ5JQXT2VGT15N2HW1.md)).
- Tests: `internal/cli/hook_test.go` before-tool table (`runHook(t, "before-tool", ...)` with `hookEvent{Cwd: ...}`) and `internal/cli/hook_shell_test.go`; add cases with `Cwd` set to `.prep/issues` and to an issue directory.
- This is a bug fix to a guardrail, not a guidance change; unit tests cover it and no eval case is needed.
