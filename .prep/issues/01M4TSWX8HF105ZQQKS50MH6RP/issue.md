Every project must explicitly settle how work is verified and documentation impact reviewed before its first issue becomes ready; capture and exploration remain possible beforehand. Retain project-to-ancestor-to-issue DoD inheritance, allow additions, and require explicit human approval and reasons for exceptions. Each manual requirement needs a result and supporting observation. Automated requirements must be executed by the agent, not prep; prep validates required check identity, result, provenance, and applicability to the work and check configuration, distinguishing agent-reported from independently verified evidence. Failed or missing required results block completion absent approved exceptions. Earlier results may be reused only while relevant implementation and check configuration remain unchanged; invalidate affected evidence otherwise. Project policy changes flag underway issues for review before completion: explicitly adopt the new policy or obtain approval to retain the old one. Policies, evidence, and exceptions are versioned. Commit timing and implementation execution remain user choices. Related: 01M4G30VB0SNZT4AJ16XR0FD88 addresses repository CI gaps, not this generic contract.
