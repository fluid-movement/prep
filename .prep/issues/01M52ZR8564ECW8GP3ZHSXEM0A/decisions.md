## D1: Prep's part in a handoff is prep guide; the rest is harness and git
date: 2026-10-17

User decisions, 2026-10-17. Prep does not assume an orchestrating harness. An issue is implemented either by a subagent of the current harness or by a different harness (Codex, Pi, which is flexible with custom agents and extensions, or any other). Prep's whole part in the handoff is prep guide <id>: for a ready or claimed issue it is the implementer's complete brief, including the role (claim, implement exactly the requirement, run the listed checks, log 'implemented, ready for check', do not complete, commit or push, log blockers and stop). That decouples the issue from where it is implemented: the orchestrator's prompt is only to run prep guide and follow it. Implementers work in their own git worktree on a short-lived local branch; worktrees are a git primitive, so prep adds no abstraction or recipe for them. The result comes back as the implementer's summary, its prep log line and the branch; the checker checks, completes and merges into main. Whether the human looks at or tests the work before the merge (for example by switching to the worktree) is between the orchestrator and the human, not prep's concern.
