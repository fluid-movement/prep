kind: code

Projects that adopt prep usually have work tracked elsewhere: TODO comments, GitHub issues, other trackers. Bringing that work in as open prep issues, so it goes through the define gate like everything else, would make adoption complete. Separate from the knowledge survey because the sources and the review differ.

## Open questions

- Which sources matter first (TODO comments, GitHub issues, a markdown list)?
- One-time import, or kept in sync with the source?
- How are imported items linked back to their source (a reference in the requirement, a frontmatter field)?
