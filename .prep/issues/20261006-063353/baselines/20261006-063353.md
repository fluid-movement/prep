prep is often adopted in a project that already has code, so the knowledge base starts empty while agents need it from the first issue. Adopting prep includes an initial survey that maps the existing project into knowledge entries, in steps small enough for an agent session and a human review.

- prep init in a repository that already has files besides .prep creates a survey research issue, already enriched so prep guide drives it; --no-survey skips it. In an empty repository there is nothing to survey and no issue is created.
- Map first: the survey's first output is a map of proposed entries (type, path, title, one-line description, scope), built from the code and from existing documentation (README, ADRs, design documents, CI configuration). The user reviews the map before any entry is written.
- The survey then gets one child issue per area of the map, so each write fits one agent session and the parent shows progress.
- Surveyed entries are written with prep knowledge new as draft, scoped, and confirmed at the surveyed commit; they become stable once the user has reviewed them.
- Importing existing work items (TODO comments, other issue trackers) is a separate issue.
