`prep edit` is a write command, not a lifecycle transition: it changes the fields of an issue's requirement record and never moves the issue between states. It follows the write pipeline in [CLI](/components/cli.md): load → plan in the domain → `CheckWrite` → `store.Apply` → stage or commit. The [domain package](/components/domain.md) owns the rules and the [markdown store](/components/markdown-store.md) the representation.

- Domain (`internal/domain/fsm.go`): add `EditInput` with optional fields (nil means unchanged) and `Tree.PlanEdit(id, in)`. Gates: the issue is not done or dropped (`G_STATE`), at least one field is given, the title is not empty (`G_TITLE`), the kind is valid (`G_KIND`), no dependency on a dropped issue (`G_DEPS`). Existence, self-dependency, cycles and depending on an ancestor are already errors in `Validate` (`internal/domain/validate.go`), so `CheckWrite` rejects them. Extend `Change` with the edited issue fields and `Tree.Apply` to apply them in memory. The edit appends a history line naming the actor and the changed fields through the existing `Change.History`.
- Markdown store (`internal/mdstore/write.go`, `records.go`): rewrite `issue.md` from the edited fields under the same compare-and-swap as other writes. A new requirement goes through the same body builder as `prep new`.
- Bug found while enriching: `newIssueBody` (`internal/mdstore/records.go`) always appends `## Open questions`, so `prep new --body` with its own Open questions section writes two. The builder keeps a body's own section and adds an empty one only when it is missing; `prep new` and `prep edit` share it.
- CLI (`internal/cli/write.go`, `cli.go`): `cmdEdit` reuses `prep new`'s parsing of `--parent`, `--depends-on` (the `multi` flag), `--body` and `--body-file`, and `Tree.Resolve` for ID suffixes. Use the flag set's `Visit` to tell "not given" from "given empty". After the write, reload and report the state and whether the issue is now stale (the `writeResult` JSON gains `stale`).
- Skill (`internal/cli/skill.md`, copied to `.claude/skills/prep/SKILL.md` by `just sync-skill`; the copies are tested equal): list `edit` among the write commands and tell agents to use it for title, kind, parent, dependencies and requirement.
- Tests in `internal/cli/cli_test.go` drive `Main` through the existing harness (`newHarness`, `ok`, `fails`, `expectState`).
