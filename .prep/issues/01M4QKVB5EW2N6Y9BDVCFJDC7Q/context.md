New package `internal/eval/fixture`. It builds on the CLI described in [CLI](/components/cli.md) and the transitions in [Issue lifecycle](/features/lifecycle.md); the project layout it produces is [Storage format](/conventions/storage-format.md).

- **Spec**: `Spec` structs in `internal/eval/fixture/spec.go`, loaded from YAML with `gopkg.in/yaml.v3` (already a dependency). Sections: `issues` (alias, title, kind, state, parent, depends_on, tags, priority, body, criteria, context), `knowledge` (alias, path, type, title, description, body), `links` (to another fixture's name), `config`, `repo`. Unknown keys are an error.
- **Build**: `Build(spec, dir, opts) (*Project, error)` runs the real binary (`opts.Binary`, default the `prep` built from this checkout) as a subprocess with `--root dir --by fixture`, in dependency order: parents before children, dependencies before dependents. To reach a state it replays the real transitions (`define`, `ready`, `claim`, `complete`, `drop`) with the minimum records the gates require (criteria, context, a `--no-impact` reason for completion).
- **Determinism seam**: `Main` in `internal/cli/cli.go` already takes the package-level `clock` and `entropy`. Read two env vars there: `PREP_TEST_NOW` (RFC3339, replaces the clock) and `PREP_TEST_SEED` (int, seeds a `math/rand` reader as `entropy`). The builder sets `PREP_TEST_NOW` per call and advances it one second per call (a process cannot keep state), so IDs and records are unique and ordered while the seed keeps the random bits fixed. Unset, production behavior is unchanged; document the variables in [CLI](/components/cli.md) as test-only.
- **Aliases**: the builder keeps `alias -> ID` in `Project.IDs` and offers `Project.Expand(s)` that replaces `{{alias}}`. Unknown alias is an error.
- **Repo section**: optional `repo: {files: {path: content}, commit: bool}`; written directly, then `git init`, a fixed author and date via `GIT_AUTHOR_*`/`GIT_COMMITTER_*`, one initial commit. Absent means no git repo.
- **Tests**: `fixture_test.go` builds a spec twice and compares the whole tree byte for byte; builds a spec reaching each state; checks `prep check` is clean on the result. Existing `newProject` in `internal/cli/cli_test.go` is left alone for now.
