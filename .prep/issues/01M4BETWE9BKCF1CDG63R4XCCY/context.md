Panel module: [Claude Code integration](/components/claude-code.md).

- `plugins/claude-code/hooks/register.tsx`: `session.start` runs `prep prime`, sets the module-level `active`, refreshes, opens the pane per `userConfig.pane` (`openAtStart`) and spawns `prep watch`. Move everything after `next(e)` except the pane opening into one `activate($)` that returns the failure message (or undefined) and does nothing when already active; session start calls it and then `openAtStart`.
- The `tool.call` Bash hook already runs after successful agent commands; when inactive and the command runs `prep init`, call `activate` and then `openAtStart` (as session start does; interactivity is not known there, so only when the session started interactive — remember `e.isInteractive` from `session.start`).
- `/prep:pane` and `/prep:focus` (`command.run` hooks) call `activate` first when inactive and answer `Not a prep project: <message>` on failure. `prep prime --json` outside a project already reports `no .prep directory found; run prep init` (`E_NO_PROJECT`), and the `prep()` helper turns that into the error message; a missing binary makes `$.process.run` throw, which carries its own message.
- `plugins/claude-code/hooks/infer.ts` parses the agent's prep commands (`issueFromCommand`, segment splitting, leading assignments, heredocs); add `runsPrepInit(command)` there, sharing that parsing.
- Tests: `plugins/claude-code/tests/panel.test.tsx`, `fakePrep(on, { isPrep: false })` makes prime fail; it needs a way to flip to a prep project mid-test. Run `claude plugin test plugins/claude-code`.
