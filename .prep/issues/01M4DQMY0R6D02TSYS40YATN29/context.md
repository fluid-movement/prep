Design: decisions D1–D7 on the parent 01M46ARM9G3492V298TM82KD45. Model on the Claude Code plugin: [Claude Code integration](/components/claude-code.md).

- **Layout**: `plugins/pi/package.json` (name, version, `peerDependencies` `@earendil-works/pi-coding-agent`, `@earendil-works/pi-tui`, `typebox` at `*`), `plugins/pi/extensions/prep/index.ts` (default factory taking `ExtensionAPI`), `plugins/pi/skills/prep/SKILL.md`. Root `package.json`: `"private": true`, `"keywords": ["pi-package"]`, `"pi": {"extensions": ["./plugins/pi/extensions"], "skills": ["./plugins/pi/skills"]}`, no dependencies, so Pi's `npm install` after cloning is a no-op. Pi loads TypeScript through jiti; no build.
- **Skill copy**: `just sync-skill` (justfile) gains the Pi copy; the test that checks the Claude Code copy against `internal/cli/skill.md` (`TestClaudeCodePlugin` in `internal/cli/cli_test.go`) checks the Pi copy too. The skill text lives in `internal/cli/skill.md` (rule 5 is the subagent rule); the briefing text comes from `cmdPrime` in `internal/cli/read.go`; both get harness-neutral wording.
- **Actor**: set `process.env.PREP_ACTOR` in `session_start` (pi's bash tool inherits the process environment); the Pi version comes from the host package's `VERSION` export or its package.json. Don't overwrite a `PREP_ACTOR` the user set.
- **Tests**: `plugins/pi/tests/*.test.ts` under `node --test` (Node 24 strips types); `just test-pi` runs them and needs Pi's packages: resolve them from the installed Pi or a dev `package.json` in `plugins/pi` (devDependencies only, never shipped as dependencies). The SDK test uses `createAgentSession` with an in-memory `SessionManager` and the faux provider from `@earendil-works/pi-ai`, loading the extension from the checkout and running a real `prep` (built by `go build`) in a temp project.
- **Development**: `pi -e ./plugins/pi/extensions/prep` or `pi install ./` (local path, loads in place); document in `plugins/pi/README.md`.
