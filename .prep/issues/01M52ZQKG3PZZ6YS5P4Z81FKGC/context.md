Simplifies write safety in `internal/mdstore` per D3 of 01M4ZCMFJ5P67XNSMKX1NPANDF. Behavior for users is unchanged except that interrupted writes are no longer rolled forward.

Where things are:
- Lock: `Store.lock` in `internal/mdstore/transaction.go` (flock via `lock_unix.go` / `lock_windows.go`, kept). Today `Load` takes a shared lock and `Apply` an exclusive one, separately. Add a store-level way to hold the exclusive lock across load, plan and write (for example `Store.Locked(func() error) error`), and make `Load` and `Apply` skip locking while it is held: flock on a second descriptor of the same file blocks even within one process.
- CLI: write commands load through `(*app).load` in `internal/cli/cli.go` and apply in `internal/cli/write.go` (around lines 184, 460, 690) and `internal/cli/knowledge.go` (`writeKnowledge`). Each write command holds the lock from load to the end of its writes; read commands keep the shared lock.
- TUI: `write` in `internal/cli/tui.go` already loads fresh before planning; it holds the lock across that load, plan and apply instead of only the in-process mutex.
- Stale-plan check: the hash snapshot (`hashes`, `hasSnapshot`, `casExpected`, `validateDirectorySnapshot`, `refreshDirectorySnapshot`, `directoryManifest`, `recordDirectoryEntries`) goes; the lock makes it unnecessary.
- Journal: the transaction journal and roll-forward recovery (`recoverTransaction`, `writeJournal`, `transactionEntry`, `applyTransaction*`, `validateRecoveryEntry`, `transactionPathAllowed`, symlink checks used only by recovery) go. Each file is still written atomically through a temporary file and rename (`syncdir_*.go` stay if used for that).
- Write order: `render` in `internal/mdstore/write.go` returns touched files; order them so the state-defining file is written last: resolution.md after supporting records on complete, ready.md last on ready, claim.md last on claim, the baseline last on define. An interruption then leaves the previous state plus harmless extra content.
- Tests: `transaction_test.go` and `fence_test.go` cases for journal and snapshot go; add tests that a write command holds the lock from load to write (a second writer blocks until the first finishes, so it plans on the new state), and that complete writes resolution.md last.
- Docs: knowledge [Local write safety](/features/local-write-safety.md) (rewrite to the lock and write order), [Markdown store](/components/markdown-store.md), [CLI](/components/cli.md) (write pipeline). Update through `prep knowledge update`.
