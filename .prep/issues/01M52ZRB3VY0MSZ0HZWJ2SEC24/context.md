The largest change of the release. It builds on the record layout (01M52ZQZBAS48ZK64MW7H85QJ4: no empty files, union merge for history.md). The TUI knowledge screen (01M52ZRH1Q2ZW3QC5KQ6A12BPC) and the finish hook (01M52ZRSZFBMWZQJPAXVHXD7M1) are separate issues: keep the TUI compiling and showing records, nothing more.

Record format: one file per record, `knowledge/decisions/<ulid>.md` or `knowledge/findings/<ulid>.md`, OKF frontmatter with type (decision or finding), title, description (required, one line), date, optional issue (the linked issue ID), optional supersedes (record IDs), optional scope (path globs), and for decisions optional outcome: true; the body holds context, choice and why (decision) or the finding. Records are never edited: no command changes an existing record. Superseded status is derived (a record is superseded when a newer record lists it in supersedes) and shown by show, find and list.

Where things are:
- Commands: `prep decide [<issue>] --title T --description D [--body text | --body-file path|-] [--supersedes <record>]... [--scope <glob>]... [--outcome]` and `prep finding [<issue>] --title T --description D [--body ...] [--scope <glob>]...` write a new record (registration in `internal/cli/cli.go`; today `decide` is `recordCmd(domain.OpDecide)` appending to decisions.md and `findings` replaces findings.md). `prep findings` goes. `--supersedes` takes record IDs or unique suffixes; D<n> numbers go.
- Domain: `Decision` and `Issue.Decisions`, `Issue.Findings` (`internal/domain/types.go`, `records.go`, `validate.go`, `guide.go`, `fsm.go`) are replaced by records looked up by issue (`t.Knowledge` entries whose issue matches; extend `domain.Entry` or add a record type). Gates: a decision issue completes when a linked decision record with outcome exists (G_OUTCOME), a research issue when a linked finding record exists (G_FINDINGS). `prep show <id>` and `prep guide <id>` list the linked records by title.
- Storage: decisions.md and findings.md parsing and writing in `internal/mdstore/records.go`, `store.go`, `write.go` go; records are written by the OKF store (`internal/okf/write.go`, `Render`/`Apply`), which keeps validating fields and refusing to overwrite an existing file.
