New package `internal/eval/transcript`. Related existing code: the activity stream ([Agent activity](/features/agent-activity.md)) records prep calls and, with the bridge, tool calls, but depends on the plugin under test, so the transcript comes from Claude's own output instead.

- **Source**: `claude -p --output-format stream-json --verbose` lines. Seen on Claude Code 2.1.296: `system`/`init` (cwd, session_id, model, tools, skills, plugins, memory_paths, claude_code_version), `system`/`hook_started` and `hook_response` (hooks that ran, with their stdout), `assistant` messages whose content holds `text` and `tool_use` (id, name, input), `user` messages with `tool_result` (tool_use_id, content, is_error), `rate_limit_event` (ignored), and a final `result` (stop_reason, total_cost_usd, usage, duration_api_ms, session_id).
- **Types**: `Transcript{Meta, Steps []Step, Final, Counts}`; `Step{Index, Tool, Input, Result, Error, Text}`; `Command{Name, Args, Project, Raw}` filled for Bash steps whose command runs `prep` (handles `&&`, `;`, pipes, `--project`, `--by`, and flags with values; unparseable stays `Raw`). Tool results are clipped when stored in the normalized form but kept whole in the raw stream.
- **Adapter**: `claudecode.Parse(r io.Reader) (*Transcript, error)`, tolerant of unknown event types and fields (Claude changes the stream between versions); an unparseable line is recorded in `Meta.Warnings`, never fatal. Parse is a pure function so tests use recorded streams in `testdata/`.
- **Raw kept**: the runner writes `stream.jsonl` and `transcript.json` per run.
- **Tests**: golden transcripts from recorded real streams (one minimal, one with prep calls and an error), command parsing table tests.
