`prep complete <id> --commit <hash>` needs the code commit to exist first, and `prep knowledge confirm` records HEAD, so an entry confirmed before committing shows as drifted right after the commit. Both force a second commit for the records. Completing a code issue becomes possible in the same commit as its code:

- Completing a code issue without `--commit` records that its evidence is the commit that adds its `resolution.md`; the agent completes first and commits code and records together. `prep show` (text and JSON) and the guide resolve it through git once that commit exists, and show it as pending until then. `--commit <hash>` keeps working for work committed earlier (other branches, squash merges). Evidence stays informational, as decided in 01M46ARQ78P8M40K4FSPVNK531.
- Knowledge drift counts from the later of the entry's `confirmed_commit` and the last commit that changed the entry file itself, and an entry file with uncommitted changes covers its scope's uncommitted changes: updating or confirming an entry in the same commit as the code keeps it current.
- `prep guide` shows `--commit` as optional for code issues; the skill describes the one-commit flow.
