`prep brief <id>` prints a text that an agent with no knowledge of prep can work from. For an implementer it holds, in this order: one line on what the agent is asked to do, the requirement, the implementation context, the acceptance criteria (numbered), the decisions that apply, the result of the last failed check if there was one, the Definition of Done, the rules of the role (implement exactly this, run the checks the context lists, never commit or push, stop and report a conflict instead of bending tests, do not read or change `.prep`), and the report format to return. `prep brief <id> --check` is the checker's version: the same issue content, the checker's rules (verify each criterion yourself, run the checks, read the change from the worktree or diff), and the checker's report format.

The text contains no prep commands and no record paths, with one exception: the report path. The brief ends by telling the agent to write its report to that file, given as an absolute path, and to answer with one line saying it is done. A report returned as the agent's final message would land in the orchestrator's context and be written to a file from there, which is the cost the hand-off decision set out to avoid (decision 01M74V5WKJV2D9E2T6J6945EZR).

`--out` writes the brief to a file and prints only its path, so an orchestrator can hand it over without the text entering its own context. Without a value it uses the default place for the issue, `.prep/local/handoff/<id>/brief.md` (`check-brief.md` for `--check`); the report path named in the brief is `report.md` (`check-report.md`) next to it, where `prep handback` looks by default. The directory is local to the machine and not versioned. Printed to standard output without `--out`, the brief names the same report path.

When the issue's work log holds a failed check that is newer than the last hand-back of an implementer, the implementer's brief includes it under its own heading, so a second pass needs nothing restated by the orchestrator.

The decisions that apply are those linked to the issue or to one of its ancestors, and current decisions whose scope matches a path the context names in backticks. Superseded decisions are left out. Decisions linked to the issue itself are given in full; those from an ancestor or a scope are given by title and description. The whole section is bounded (about 6,000 characters, own decisions first, then by specificity); when the bound cuts or drops one, the brief says so.

A brief is given only for a code or research issue that is ready or in progress, not stale, with dependencies done; otherwise the command fails and names what is missing. For a research issue the report asks for findings instead of a criteria verdict.

Why: decision 01M72AV3FRS077RJ3DPXZFX23M (hand-off by brief). The orchestrator wrote every hand-off by hand in the daypack sessions, and implementers need a prep installation today only to read their issue and report back.

The report format is defined once and shared with `prep handback` (sibling issue): Markdown with the headings `## Summary`, `## Criteria` (one line per number: met or not met, with the evidence), `## Decisions` (each a title line and a reason), `## Findings`, `## Problems`. Empty sections may be left out.
