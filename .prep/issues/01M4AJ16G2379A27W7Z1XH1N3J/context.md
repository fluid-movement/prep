The issue filter bar lives in `internal/tui/app.go`: `f` opens it (`m.filtering`, `m.input`), `filterKey` handles keys (enter applies through `parseFilterText` and `setFilter`, esc clears), `listPane` draws the bar above the rows. The values come from `domain.Tree.QueryFlags` (`internal/domain/flags.go`, see [Domain](/components/domain.md)), the same source as `prep flags`.

- **Completion context** (a pure function, testable): from the input text, the word being typed decides the candidates: a word starting with `--` → flag names; a word after a list flag (`--state`, `--kind`, `--tag`, `--priority`, `--under`) → that flag's values, narrowed by what is typed (prefix first, then substring; for `--under` also the title), with comma lists completing the part after the last comma and skipping values already listed. Booleans and `--text` offer nothing after them; bare words offer nothing (they search titles).
- **Picker**: up to six candidates under the input, each with its count (and title for `--under`); the highlighted one uses the selection background. `↑`/`↓` move, `tab` inserts the highlighted candidate (a flag gets a trailing space; a value replaces the typed part), enter still applies the filter, esc still clears. A click on a candidate inserts it (mark `pick:n` like other clickable rows, see [TUI mouse](/components/tui-mouse.md)). The knowledge filter bar is out of scope.
- **Bug fixed on the way**: `parseFilterText` hard-codes which flags take a value and misses `--priority`, so `--priority high` became a text search for "high". It uses `QueryFlags` kinds instead.
