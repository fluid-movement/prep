The project configuration is read and written only in `internal/mdstore` (see [Markdown store](/components/markdown-store.md) and [Storage format](/conventions/storage-format.md)):

- `Store.LoadConfig` (`internal/mdstore/store.go`) reads `.prep/config.yaml`; a missing file yields defaults (no views). It becomes: read `config.yaml`, else `config.yaml.dist`, else defaults. `Store.Load` puts the result in `project.Config` and reports a parse error as P003 (`CodeConfigInvalid`) with `config.yaml` as the file; the diagnostic must name the file that was actually read.
- `projectFiles` in `store.go` is the allowlist of entries in `.prep`; it gains `config.yaml.dist`. `.gitignore` is already allowed.
- `Store.Apply` writes `Change.Config` (from `Tree.PlanConfig`, used by the TUI settings in `internal/tui/editing.go`) through `renderConfig(current, cfg)` to `config.yaml`. When `config.yaml` is missing, `current` must come from `config.yaml.dist`, so the leading comment header is kept.
- `DefaultConfig` and `Store.Init` (`prep init`, `internal/cli/write.go`) write `config.yaml`; they write `config.yaml.dist` and `.prep/.gitignore` with the line `config.yaml` instead. The header comment "project-level only" changes to explain the dist/own split.
- Staging: after every write, `record` in `internal/cli/cli.go` runs `gitx.Stage` (`git add -A -- paths`). Once commit mode is removed (01M4AJ9DN4CK5S4WX2N68VBR98) staging is the only path. `git add` on an ignored path fails ("paths are ignored"), which would make every TUI settings save print a warning. Paths that are gitignored are left out of `record` (`git check-ignore`), so personal config writes are never staged.
- This repository: `git mv .prep/config.yaml .prep/config.yaml.dist`, add `.prep/.gitignore`, then copy the dist file back to `config.yaml` locally. No migration code.
