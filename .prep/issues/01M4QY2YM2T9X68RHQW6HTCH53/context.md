Run: `prep eval run --tag plugin-ab --variants none,skill-only,hook-only,current --models haiku --n 5 --max-usd 3 --yes` (about $0.50 on haiku at API prices; the plan was 5 cases x 4 variants x 3 runs for about $0.30 - use 5 runs). Then `prep eval compare <run> --variants current,none` and the same for the other pairs; `prep eval errors <run>`. Add sonnet only if the haiku result is unclear and the budget allows (about $2).

What to look at beyond pass rates: `calls` and cost per run (the skill's token cost shows up as input tokens on every run: compare `tokens_in` between `none` and `skill-only` in `cells.json`); whether the agent loaded the skill (`Skill` steps in `transcript.json`; in the full haiku run the agent launched the prep skill in most sessions) and whether it ran `prep prime` itself when the hook was absent; the actor named in prep commands (`--by`) - without the bridge the agent names itself, with it `PREP_ACTOR` is set by the plugin.

Caveats: in the fixture the `.prep` directory and a `README` hint exist, so `none` is not "an agent that never heard of prep" - it is "an agent that finds a `.prep` directory", which is the realistic case for a project that has prep but a user without the plugin; say so in the findings. `skill-only` removes the bridge too; that does not change what the agent does, only what the activity stream records.
