Query flags are parsed in one place, `domain.ParseFilter` (`internal/domain/query.go`), shared by `prep list`, saved views and the TUI filter bar; `prep list` adds `--view` and `--tree` (`cmdList` in `internal/cli/read.go`). See [Domain](/components/domain.md) and [CLI](/components/cli.md).

- `domain.QueryFlags(t *Tree) []FlagInfo` describes every filter flag in `ParseFilter`'s order: name, kind (list of values, boolean, free text), a one-line description, and the values available now with the number of issues each matches: `--state` (`States`), `--kind` (`Kinds`), `--priority` (`Priorities`, effective level), `--tag` (tags in use, sorted), `--under` (issues with children: ID and title), `--text` (free text), the booleans `--stale`, `--actionable`, `--blocked`, `--parent`, `--leaf` with how many issues each selects, and `--top`. This is the value source the TUI filter bar issue (01M4AJ16G2379A27W7Z1XH1N3J) reuses.
- `prep flags` (`internal/cli/read.go`, read command) prints them grouped per flag, then the list-only `--view` (saved view names with their queries) and `--tree`. `--json` emits the same structure.
- A test keeps `QueryFlags` and `ParseFilter` in sync: every described flag parses, with each listed value.
