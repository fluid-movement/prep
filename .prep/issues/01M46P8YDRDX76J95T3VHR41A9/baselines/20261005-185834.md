The CLI is prep's API: every change to the data goes through a command that carries content, and the storage adapter decides the representation. Agents today write context, decisions, acceptance criteria, Definition of Done changes, history and findings by editing files, and prep guide lists file paths under Write. Each record gets a write command that matches its semantics, with --json and validation before writing:

- prep context <id> --body <text> | --body-file <path|-> replaces the implementation context.
- prep findings <id> --body | --body-file replaces the findings of a research issue.
- prep decide <id> --title <text> [--body | --body-file] [--supersedes <decision id>] [--outcome] appends the next decision (D1, D2, ...) dated today. Decisions are append-only; --supersedes must name an existing decision, and --outcome is only for decision issues.
- prep criterion <id> with --add <text> (repeatable) and --check, --uncheck, --remove <n> (repeatable, numbered as prep show lists the criteria before the call) changes acceptance criteria.
- prep dod <id> with --add <item>, --opt-out <item> --reason <text>, and --remove <item> changes the issue's Definition of Done additions and opt-outs.
- prep log <id> <text> appends a timestamped history line naming the actor.

They work on any unresolved issue and never change state. prep guide lists these commands under Write instead of file paths, and the skill tells agents to use them. Hand edits stay possible for humans and remain caught by prep check; the skill's "Without the binary" section keeps file editing as the fallback for cloud sessions until a better solution exists.
