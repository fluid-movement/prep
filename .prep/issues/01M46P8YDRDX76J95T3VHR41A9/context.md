Six write commands, none a lifecycle transition. They follow the write pipeline of [CLI](/components/cli.md) and the pattern of `prep edit` (`cmdEdit` in `internal/cli/write.go`, `Tree.PlanEdit` in `internal/domain/fsm.go`): plan in the [domain](/components/domain.md), `CheckWrite`, `store.Apply`, stage or commit, report. All refuse done and dropped issues (`G_STATE`).

- Domain: `Change` describes the record changes, not files. Context and findings carry the new text; a decision carries the new `Decision` (the domain picks the next `D<n>` and today's date); acceptance carries operations (check, uncheck and remove by 1-based index, add text; DoD add, opt-out with reason, remove by item text) so the adapter can apply them without losing prose a human wrote between criteria; a history line uses the existing `Change.History`. Gates: index in range (`G_CRITERION`), `--outcome` only on decision issues and findings only on research issues (`G_KIND`), `--supersedes` names an existing decision (`G_DECISION`), opt-out needs a reason and DoD remove needs a matching item (`G_DOD`). `Tree.Apply` mirrors each change in memory for `CheckWrite`.
- [Markdown store](/components/markdown-store.md) (`internal/mdstore/write.go`): context.md and findings.md are rewritten; decisions.md gets the rendered entry appended (`## D<n>: <title>`, `date:` on the next line, optional `supersedes:` and `outcome: true`, blank line, body); acceptance.md is edited line by line with the same rules as `parseAcceptance` (criteria are checkboxes outside the `## Definition of Done` section; additions go after the last criterion; DoD lines go into that section, created when missing). Every file is compare-and-swapped against the hash seen at load.
- CLI (`internal/cli/write.go`, `cli.go`): `context`, `findings`, `decide`, `criterion`, `dod`, `log`; `--body`/`--body-file` through `readBody`. `prep show` (`internal/cli/read.go`) numbers criteria so `--check <n>` has a reference.
- Guide (`internal/domain/guide.go`, `stepContract`): instructions and the Write list name the commands; `Pointer` gains a `command` field next to the path. The define step points at `prep edit --body-file` for the requirement.
- Skill (`internal/cli/skill.md`, synced by `just sync-skill`): use the commands; the "Without the binary" section keeps file editing for cloud sessions (01M46PWX38AZN55Q6T8TE93959 tracks a better answer).
- Tests: `internal/cli/cli_test.go` with the existing harness.
