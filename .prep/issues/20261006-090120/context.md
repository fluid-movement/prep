Priority follows the path tags take through every layer ([Storage format](/conventions/storage-format.md), [Domain](/components/domain.md), [CLI](/components/cli.md), [TUI](/components/tui.md), [Claude Code integration](/components/claude-code.md)).

- Domain (`internal/domain`): a `Priority` type with `PriorityCritical`, `PriorityHigh`, `PriorityMedium`, `PriorityLow`, a rank, and `ParsePriority` (empty means medium). `Issue.Priority` in `types.go` (JSON `priority`, always present in output as the effective level). `NewIssueInput.Priority` and `EditInput.Priority *Priority` in `fsm.go`; the tags-only rule (`tagsOnly`, edits of resolved issues) widens to metadata-only edits: tags and/or priority. Priority never enters the baseline or the stale comparison. `validate.go`: a new code `I027` for an unknown stored level, next to `CodeTagInvalid` in `diag.go`.
- Ordering: a helper `Tree.ByPriority(ids)` (stable: priority rank, then ID). `Tree.Query` returns its result through it; `Tree.TreeOrder` walks roots and each parent's children in that order; `cmdPrime` in `internal/cli/read.go` orders `Next` and `Stale` with it (parents keep ID order). `Tree.IDs` stays chronological.
- Filter: `Filter.Priorities` parsed by `ParseFilter` from `--priority` (repeatable, comma-separated), applied in `Query`; saved views and the TUI filter bar (`parseFilterText`) go through `ParseFilter`, so they get it for free; add `--priority` to the filter-bar key hint (`filterKeys`).
- Storage (`internal/mdstore`): `issueFM` gains `Priority string yaml:"priority,omitempty"` after `tags`; medium is written as empty; `write.go` copies it with the other edit fields. `KnownFields(true)` stays. No schema bump (decision D3). Contract corpus: a valid tree with priorities and an invalid one with a bad level.
- CLI: `--priority` on `new` and `edit` (`write.go`, usage strings in `cli.go`), `--priority` in `list`'s query flags; `summary` gains `priority` (`omitempty` for medium is not used: JSON always carries the effective level); text output of `list` marks non-medium levels (e.g. `!crit`, `!high`, `low`) and `show` prints `priority:`; `prep next` inherits ordering from `Query`.
- TUI: `ui.Row` gains a priority mark rendered before the title (critical in the error tone, high in warning, low subtle, medium nothing); detail meta line shows it; a `p`-free action letter (`y` is taken by copy; use `i` "Set priority") opens a `ui.MenuRow` picker of the four levels and writes through `PlanEdit` with only `Priority` set, allowed on resolved issues. Goldens and gallery rows update.
- Side panel (`plugins/claude-code`): `PrepSummary.priority` and `PrepShow.issue.priority` in `types/index.d.ts`; the live header and the project tree mark non-medium levels with the same tones.
- Knowledge: `out-of-scope.md` drops priorities from "none for now"; storage-format lists the field.
- Tests: domain (parse, ordering, edit on resolved, stale untouched, validation), CLI lifecycle (new/edit/list --priority/next order/show JSON), TUI snapshot and action, plugin tests for the marks.
