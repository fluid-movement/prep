The Claude Code panel draws with Claude Code's own theme colors, while `prep tui` uses the prep theme; the same states and notes look different in the two places. The panel takes its colors from prep instead: a read command, `prep theme colors [--theme <name>] --json`, prints a resolved theme (the eight tokens and the colors prep derives from them: one per state, kinds, borders), and the plugin paints with those hex colors (Claude Code's Text accepts raw colors).

- Without `--theme`, the command prints the configured theme, or `default` when none is configured (the terminal background plays no part outside the TUI).
- The plugin gets one option, `theme` (plugin userConfig, next to `pane`): empty follows prep's configured theme; a theme name (built-in or custom) themes the panel only; `claude` keeps Claude Code's own colors.
- The derived colors come from prep, so the panel never repeats the state mapping.
- The plugin reads the colors at session start and when `prep watch` reports a change, so a theme switch in the TUI recolors the panel.
- When the command fails (an older binary, an unknown theme), the panel draws with Claude Code's colors, as today.
