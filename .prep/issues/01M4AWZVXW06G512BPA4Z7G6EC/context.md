- **Derived colors**: the state, kind and border mapping lives in `internal/tui/theme` (`stateTokens`, `Kind`, `Border: subtle`) ([Palette and themes](/components/palette.md)). It moves to `internal/palette` (`StateToken`, `KindToken`, `BorderToken`) so the CLI prints the same mapping the TUI draws with, without importing the TUI.
- **Command**: `prep theme colors [--theme <name>] [--json]` in `internal/cli/theme.go` next to list and new; the theme is `--theme`, else `.prep/config.yaml` `theme`, else `palette.Default`; resolved with `palette.Resolve(name, cfg.Themes)`, errors as `E_INVALID`/not found. Outside a prep project only built-ins resolve. JSON: `theme`, `light`, `tokens` (the eight, hex), `states` (each state → hex), `kinds` (each kind → hex), `border`. Text: one `name #hex` line per token, then states. Help line in the command table (`cli.go`), [CLI](/components/cli.md) entry.
- **Plugin**: `plugins/claude-code/.claude-plugin/plugin.json` `userConfig.theme` (string, default empty); `hooks/register.tsx` reads `options.theme`, runs `prep theme colors --json [--theme]` at activation and on each `prep watch` line, keeps the result in `$.state` `prep.colors` (declared in `types/index.d.ts`); `hooks/panel.tsx` replaces the fixed `ACCENT`/`STATE` and literal theme keys with a palette object built from the colors, or the current Claude Code keys when the option is `claude` or the command failed. Claude Code's `Color` admits hex strings.
- **Tests**: Go tests for the command (default, configured, `--theme`, custom, unknown) and that `internal/tui/theme` and the JSON agree; `tests/panel.test.tsx` draws with hex colors and with the fallback.
