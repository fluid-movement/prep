The record redirect hook (before-tool) blocks a Bash command whenever a word in its text looks like a path under the records directory, so it blocks legitimate calls: prep commands whose arguments or message text name a record path (prep log, prep edit --body), git commands on records (git add, git rm, git checkout --ours, git ls-files, git diff during a merge), and heredocs or quoted strings that only mention a path (commit messages, issue bodies, scripts writing elsewhere). On 2026-10-17 it blocked creating this very issue. It must match only the paths a call actually reads or writes: for Bash, the file arguments and redirections of the command in each segment, never text inside quotes passed as a value, heredoc bodies, or arguments of prep and git. Direct reads (cat, sed, grep on record files) and writes (redirection into, sed -i, cp, mv, rm, tee onto record files) stay redirected, and Read, Edit, Write, Grep, Glob and apply_patch keep their current path checks.
