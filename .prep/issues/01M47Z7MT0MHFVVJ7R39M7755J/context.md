OKF v0.2 (checked against the spec): index.md MAY appear in any directory and may be generated; it lists the directory as grouped sections of `* [Title](url) - description` lines; only the bundle-root index.md may carry frontmatter, `okf_version: "0.2"`; index.md and log.md are reserved names; status allows draft, stable and deprecated; producers may add keys and consumers keep unknown ones.

- [OKF store](/components/okf-store.md) (`internal/okf/index.go`): `IndexFiles(entries)` computes the index of every directory that holds entries (and its ancestors): an Entries section with the directory's entries sorted by path, and a Directories section linking each subdirectory's index.md with its entry count; the root adds the okf_version frontmatter. No entries, no index files. `WriteIndexes(dryRun)` writes changed index files atomically and removes index.md files in directories without entries. `Apply` calls it after every knowledge write; `Load` skips log.md and reports missing, outdated or extra index files as K007 (warning, fixable by prep fmt or prep fix).
- [Domain package](/components/domain.md): `validateKnowledge` accepts status deprecated; [Knowledge base conventions](/conventions/knowledge-base.md) keeps "delete stale entries" as the convention and documents index files and log.md.
- [CLI](/components/cli.md): `prep fmt` (and `--check`) and `prep fix` include the index files.
- Contract corpus (`testdata/contract`): valid trees get their generated index files; a new valid case with an outdated index expects K007.
- This repository gets its index files generated by prep fmt as part of the change.
