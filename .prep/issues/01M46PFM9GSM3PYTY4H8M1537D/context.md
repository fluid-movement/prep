Follows the write pipeline of the [CLI](/components/cli.md) and extends the knowledge store port ([Architecture](/components/architecture.md), [OKF store](/components/okf-store.md)), which only reads today.

- Domain (`internal/domain`): a `KnowledgeEdit` (entry path, new or update, optional type, title, description, status, scope, confirmed commit, body, actor and time) carried by `Change.Knowledge`. `Tree.PlanKnowledge` checks what the domain knows without the adapter: path form (`NormalizeEntryPath`, no `..`, no rename), new entries must not exist and need type, title, description and body, updates must exist and change something. `Tree.Apply` replaces or adds `Change.KnowledgeEntry`, so `CheckWrite` runs the existing `validateKnowledge` rules (fields, status, broken links) on the result.
- Port: `KnowledgeStore` gains `Render(*KnowledgeEdit) (*Entry, error)`, which builds the would-be file and parses it back into an `Entry` with links, and `Apply(*KnowledgeEdit) ([]string, error)`, which writes it. The OKF adapter edits the frontmatter as a YAML node so unknown keys and their order survive; new entries get the canonical key order and `generated: {by, at}` like the existing entries. Writes are atomic (temp file plus rename).
- Confirm: `gitx` gains a `Head` call; confirm loads with drift for `--drifted`, refuses entries without scope and runs one write per entry.
- CLI: `prep knowledge` dispatches `new`, `update`, `confirm` (`internal/cli/knowledge.go`); `record` stages the written files. `--scope` is repeatable and `--scope ''` clears it, like `prep edit --depends-on`.
- Guide (`internal/domain/guide.go`): the implement step's documentation instruction and Write list name `prep knowledge update/new/confirm` instead of the directory. Skill (`internal/cli/skill.md`, synced) lists the group.
- Tests in `internal/cli/cli_test.go` with a git repository in the temp project for confirm.
