First screen of the TUI, composed only from the [TUI design system](/components/tui-design-system.md) components (`internal/tui/ui`) and theme. Reads only; no writes in this issue.

- Entry: `cmdTUI` in `internal/cli/tui.go` already checks for a terminal and runs the gallery. Without `--gallery` it now runs `tui.Run`, passing a loader (`func() (*domain.Tree, error)`, the CLI's `a.load(false)`) and the `.prep` directory to watch, so `internal/tui` does not depend on the storage adapters ([Architecture](/components/architecture.md)).
- Data: the same query engine as `prep list` ([Domain package](/components/domain.md)): `domain.ParseFilter` on each saved view's flags, `Tree.Query`, then `State`, `Stale`, `Blocked`, `ChildProgress` per row, mirroring `summarize` in `internal/cli/read.go`.
- Saved view order: `Config.Views` is a map, so tab order is lost. The markdown store's `LoadConfig` (`internal/mdstore/store.go`) also records the order of the `views:` keys from the YAML node into a new `Config.ViewOrder`; `prep views` uses that order too instead of sorting.
- History: `history.md` is read for canonical checks but not kept. Parse it into a new `Issue.History` string so the detail pane can show it.
- Screen (`internal/tui/app.go`): header with the app name and the tabs bar with counts; body split by `ui.Split` into the list pane and the detail pane (titled `ui.Pane`, focus color on the active one); key help footer. Below the width where both panes fit, only the focused pane shows. The detail is a markdown document built from the issue (title, state, kind, parent, depends on, blocks, requirement, open questions, context, decisions, numbered acceptance criteria, Definition of Done, history, resolution), rendered by `ui.Markdown` into a Bubbles viewport and cached per issue, width and reload.
- Live reload (`internal/tui/watch.go`): fsnotify on `.prep` and every directory under it (fsnotify is not recursive; new directories are added as they appear), debounced, delivered as a reload message. The selected issue stays selected by ID across reloads. A load error keeps the last good data and shows the error in the footer.
- Copy ID: OSC 52 through the renderer's termenv output (`Output().Copy`), which works over SSH; a short notice confirms it.
- Tests: model tests drive `Update`/`View` with a fixed theme and a fixture project built in a temp dir; a golden snapshot of the screen at 100×30; a watcher test that a file change produces a reload.
