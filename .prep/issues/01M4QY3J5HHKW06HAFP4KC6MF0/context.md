Where: `execMatrix` in `internal/cli/eval_run.go` creates `work` with `os.MkdirTemp("", "prep-eval-work-")`, `matrix.Live.Run` passes it as the run environments' parent, `run.Record.Release(pass)` keeps the environment of a failing run and returns its path, which ends up in the stored `RunResult.Dir` (printed as `see <dir>` by `prep eval report --failures`). `defer os.Remove(work)` only removes it when empty. Why under the temp directory and not in `eval/results/`: fixtures inside a git checkout make prep stage into the surrounding repository and break cross-project linking (found in the first full run).

Options. (1) `prep eval prune --keep N` also removes the kept workspaces of the runs it deletes (they are recorded in `cells.json`; delete the `Dir` of each failed run), and a new `prep eval clean` removes every `prep-eval-work-*` older than a day. (2) Keep only the files that matter (`.prep`, changed sources) instead of the whole environment (the Claude config dir with its caches is most of the size - measure first). (3) Default `--keep` off for runs that pass and cap the number of kept workspaces per run (say the first 3 failures per cell), since the other failures add little.

Test: with a fake `claude` (see `internal/cli/eval_test.go`) run a failing case, assert the directory exists after the run, then that prune removes it. Document in [Agent behavior tests](/components/eval.md).
