Codex plugin package: `plugins/codex/.codex-plugin/plugin.json`, `skills/prep/SKILL.md`, and `hooks/hooks.json` with `hooks/prep_hook.py`. `.agents/plugins/marketplace.json` advertises `./plugins/codex`. `just sync-skill` copies `internal/cli/skill.md` then appends the Codex activity attribution note; `just release` and the release workflow keep Codex manifest and marketplace versions synchronized.

`internal/setup/codex` registers the `codex` harness. It uses `codex plugin list --json`, marketplace list/add/remove, and plugin add/remove to install the release-pinned plugin; for releases it sparsely fetches `.agents/plugins` and `plugins/codex`. The development source override is `PREP_CODEX_PLUGIN_SOURCE`; `just install` sets both Claude and Codex source overrides for its refresh.

`prep_hook.py` detects `.prep/` upward from the hook `cwd`. Session start adds `prep prime --hook`; user prompt submission adds issue-search/guide directions and includes `prep guide` output when a full issue ULID is present. Supported direct `.prep` edits through Bash or `apply_patch` are denied with a reason; the Bash hook adds `PREP_SESSION` and `PREP_ACTOR=codex`. PostToolUse sends supported events to `prep activity add`, excluding prep commands. Errors fail open. Codex requires the user to review and trust plugin hooks through `/hooks`; without trust the skill remains available, but automatic hooks do not run. Codex does not expose Claude bridge token/cost data here.
