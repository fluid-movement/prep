Implements the Claude Code side of the setup interface from 01M48721G8Y21HT0ZGAXB5QZF2 and replaces this repository's project-level [Claude Code integration](/components/claude-code.md).

- Layout in this repository: `.claude-plugin/marketplace.json` at the root names the marketplace `prep` and lists the plugin `prep` with source `./plugins/claude-code`. The plugin: `.claude-plugin/plugin.json` (name `prep`, version), `skills/prep/SKILL.md` (kept identical to `internal/cli/skill.md` by `just sync-skill` and a test, like the cloud copy), `skills/status/`, `skills/next/`, `skills/guide/` (the commands, invoked as `/prep:status`, `/prep:next`, `/prep:guide`), `hooks/hooks.json` with a SessionStart hook in the `settings.json` shape. A later `mod/` directory takes the TUI pane (01M46ARKA817KMB2C92WMNH2QP).
- Hook: `prep prime --hook --plugin "${CLAUDE_PLUGIN_ROOT}"`, wrapped so a missing binary exits 0 silently. `--hook` makes prime print nothing outside a prep project instead of an error; `--plugin` makes it read the plugin's `plugin.json` version and put a warning first when it differs from the binary, naming `prep update`.
- Versions: `just release vX.Y.Z` sets the version in `plugin.json` and `marketplace.json`, commits and tags; the release workflow fails when the tag and the plugin version differ. Setup adds the marketplace pinned to the binary's tag (`fluid-movement/prep#vX.Y.Z`) so the installed plugin matches the binary; moving to a new version re-adds the marketplace at the new tag and reinstalls.
- `internal/setup/claudecode.go`: `Detect` finds `claude` on PATH; `Installed` reads `claude plugin list --json`; `Install` runs `claude plugin marketplace add` and `claude plugin install prep@prep --scope user --json`; `Remove` uninstalls the plugin and removes the marketplace. Development builds (no release tag) install from the local checkout path instead, so the plugin can be tried before a release.
- This repository: `.claude/settings.json` hook and `.claude/commands/` go away; `.claude/skills/prep/SKILL.md` stays for cloud sessions.
- Tests: a fake `claude` script on PATH records invocations and serves `plugin list --json`; prime `--hook` and `--plugin` covered in `internal/cli` tests; `claude plugin validate` checks the plugin when Claude Code is available.
- Docs at completion: [Claude Code integration](/components/claude-code.md) rewritten for the plugin, [Release, install and update](/components/release.md) for `just release`.
