Section names become XML tags (`<prep>…</prep>`).
- **Version check**: `pluginAlert(dir)` in `internal/cli/read.go` reads `.claude-plugin/plugin.json`; generalize it to read `package.json` when there is no plugin manifest, so `--plugin <package root>` works for Pi, with neutral wording ("the prep integration").
- **Activity**: `pi.on('tool_result')` (bash, powershell, read, edit, write, grep, find, ls; skip `isError`; never return a value) and `message_end` for assistant messages with `usage` (input, output, cacheRead, cacheWrite, cost), plus `ctx.getContextUsage()`; each event piped as JSON to `prep activity add` without awaiting the turn. Map Pi tool names to the format's tool and area fields exactly as the Claude Code bridge does.
- **Tests**: the SDK session test asserts the section (present, identical across two turns, absent outside a prep project, recomputed after compaction) and that `prep activity` shows the faux session's tool calls and requests.
