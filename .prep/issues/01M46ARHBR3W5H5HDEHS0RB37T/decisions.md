## D1: Read-only knowledge, no review step
date: 2026-10-06

Decided with the user: knowledge is written by agents for agents. The TUI shows it so a person can see what the agents know and why, but never edits it, and there is no review step at completion: by the time knowledge is written everything is resolved. Alternatives: editing entries via $EDITOR or inline; reviewing knowledge changes alongside other content at completion.

## D2: Knowledge screen like check and settings, attention from the check
date: 2026-10-06

The knowledge view is a screen reached with a melody (k from the issue screens would clash with j/k movement, so b for bundle; ? lists it), with the list on the left and the entry on the right like the issue views. Attention marks come from the same Options.Check load the check screen uses, because drift needs git and must stay out of the frequent reloads. Alternatives: knowledge as extra tabs among the saved views (mixes two kinds of rows); computing drift on every reload (about 170 ms per load).
