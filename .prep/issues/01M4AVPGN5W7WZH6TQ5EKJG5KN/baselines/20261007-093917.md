Projects initialized with prep 0.1.0 break with the current binary: their committed `.prep/config.yaml` sets `commit_mode` (now an unknown key, so the whole config is rejected and every saved view disappears), views use `in_progress` (now `in-progress`), and there is no `config.yaml.dist` or `.prep/.gitignore`, so personal settings would be committed. `prep check` reports the problem as fixable, and `prep fix` converts such a project:

- drops `commit_mode` and rewrites `in_progress` to `in-progress` in view queries;
- when `config.yaml` is tracked by git and no `config.yaml.dist` exists, renames it to `config.yaml.dist` (staged as a rename) and keeps a local `config.yaml` copy;
- adds `.prep/.gitignore` with `config.yaml` when missing.

The user then commits the result. A project already in the current format is left alone.
