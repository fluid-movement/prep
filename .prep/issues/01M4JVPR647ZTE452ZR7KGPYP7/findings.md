Chosen: an offscreen snapshot mode in the app itself, plus `swift test` for PrepKit against the real binary. `PrepDesktop <project> --snapshot out.png [--select <id>] [--tab …] [--entry …] [--size WxH] [--appearance …]` (`just desktop-snapshot`) builds a real window loaded through the CLI, keeps it on the window server but off every screen, renders it with `cacheDisplay` and exits; the agent reads the PNG. Proven on this repository and a fresh project: issue tree, detail with links, transitions and criteria, knowledge entries, the agent feed, light and dark.

macOS 26 draws Liquid Glass (sidebar panel, toolbar platters) in the window server, so `cacheDisplay` paints glass as blank shapes and skips what they hold. The snapshot composites around it: lists outside glass are cleared and their visible rows drawn one by one, then each glass panel gets a flat stand-in with its content views drawn on top, then the glass lists' rows, then toolbar items and the title. Remaining limit: rows inside the glass sidebar lose their vibrant colors (dark text, white state dots); layout and content are right. `PREP_SNAPSHOT_TREE=1` prints the view hierarchy for structural checks.

Alternatives: `screencapture -l` and ScreenCaptureKit need Screen Recording permission (`screencapture` failed with "could not create image from window" here); XCUITest needs an Xcode project and Accessibility permission; `ImageRenderer` leaves AppKit-backed controls (lists, text fields, menus) blank; rendering the layer tree draws glass the same blank way. An accessibility dump would give text but not layout.

Also found while proving it: each exit left its `prep watch` child running, so `prep watch` now ends when its parent is gone and the app stops watchers on quit.
