New package `internal/eval/env`, used by the session runner ([Session runner](01M4QKVBYFPQT50HP41EHZ6F4X)) and variants ([Variants](01M4QKVCW6CMS3Z21PVCK9RA01)). Integration facts: [Claude Code integration](/components/claude-code.md).

- **Directories**: `Env{Home, ConfigDir, StateDir, Bin, Workspace}` created under a per-run temp dir. The harness process environment is built from scratch, not filtered from the caller's: `HOME`, `CLAUDE_CONFIG_DIR`, `XDG_STATE_HOME`, `XDG_CONFIG_HOME`, `PATH` (pinned binary dir, then the system dirs), `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1`, the auth variable, and `TERM`, `LANG`, `TMPDIR`. `PREP_ACTOR` and `PREP_SESSION` are unset; the plugin's bridge sets them.
- **Pinned binary**: `PinBinary(path)` copies the binary into `Bin`, so a rebuild mid-run cannot change a run; `just build` produces the default.
- **Plugin**: the variant's plugin directory loads through `claude --plugin-dir`, never `prep setup`, so the real installation is untouched. The hook runs `command -v prep`, so PATH matters.
- **Why a fresh config dir**: `--bare` skips hooks and skills, which are what is under test; `--setting-sources project,local` keeps the login but user skills and memory still load from the real home. A private `CLAUDE_CONFIG_DIR` with passed-through auth is the sure way, and the leak check verifies it.
- **Leak check**: `Probe(env)` runs a fixed prompt asking the agent to list the skills, hooks and memory it sees, parses the answer, and compares with the variant. The CLI entry (`prep eval doctor`) comes with [Initial suite](01M4QKVD1SBR79P1QYECT9KYQ9).
- **Tests**: unit tests on the built environment (no caller variable inherited; PATH first entry; auth required) and a fake `claude` script (shell) that records its environment and arguments.
