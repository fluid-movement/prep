Agents read knowledge entries by opening the files, because prep has no knowledge read command: `prep guide` names candidate entries and the agent `cat`s them whole. In a measured bootstrap survey (fathom, session 704a70a0), five Explore subagents spent about 72k tokens of tool output on knowledge and issue files, much of it the same overview, index and entries read again by each agent. Reads through prep can be narrow (one section, an outline) and later filtered (relevance, size caps) without relying on the agent to read carefully.

- `prep knowledge list [--type] [--status] [--scope] [words]`: one line per entry with path, type, title, description and size (≈ tokens); `--json` adds scope and section headings.
- `prep knowledge find <query> [--max N]`: ranks entry sections against the query (title, description, scope, headings and body; prefix, substring and one-typo matches) and prints the best sections with a matching line, as `<entry>#<anchor>` references.
- `prep knowledge show <entry>[#anchor]... [--outline]`: prints entries or single sections; `--outline` prints title, description, scope and the headings with anchors and sizes instead of the body. Unknown anchors fail with the available ones.
- Entry references accept the forms the knowledge writes accept (`components/cli`, `/components/cli.md`, `.prep/knowledge/components/cli.md`).
- `prep guide` points at `prep knowledge show` for its candidates instead of file paths; the skill tells agents to read knowledge through these commands, not the files.
- All three are reads: they never change anything and appear under read commands in `prep help`.
