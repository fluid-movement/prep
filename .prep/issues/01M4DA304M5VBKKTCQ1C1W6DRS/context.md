The knowledge reads are domain queries over the loaded tree, printed by the CLI; nothing new in the stores.

- **Domain** (`internal/domain/knowread.go`, beside the filter in `internal/domain/knowview.go`): `Sections(body)` splits an entry body at markdown headings (skipping fenced code), each section with an anchor (`Slug`), its text including subsections, and its own text up to the next heading for scoring. `Tree.FindKnowledge(query, limit)` ranks sections. Entry bodies are already loaded (`okf.Store` sets `Entry.Body`; see [OKF store](/components/okf-store.md)).
- **CLI** (`internal/cli/knowledge.go`): `cmdKnowledge` dispatches `list`, `find` and `show` next to the writes; `list` reuses `domain.ParseKnowledgeFilter` and `Tree.QueryKnowledge` (the TUI's knowledge filter, [TUI knowledge view](/components/tui-knowledge.md)); references go through `domain.NormalizeEntryPath`, with an optional `#anchor`. `prep help` lists commands by their `write` flag, so the knowledge reads get their own read entry in the command table (`internal/cli/cli.go`). See [CLI](/components/cli.md).
- **Guide** (`cmdGuide` in `internal/cli/read.go`): the candidates header and lines point to `prep knowledge show <entry>`; JSON is unchanged. [Agent context](/features/agent-context.md) describes what guide lists and why.
- **Skill**: `internal/cli/skill.md` and `plugins/claude-code/skills/prep/SKILL.md` (kept identical) get the read commands and the rule to read knowledge through them.
- Sizes print as ≈ tokens (bytes/4) so an agent can choose between an outline, a section and the whole entry.
