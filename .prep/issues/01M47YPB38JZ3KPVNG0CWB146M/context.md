- Domain (`internal/domain/bootstrap.go`, [Domain package](/components/domain.md)): `Tree.Bootstrapped()` is true once the `/overview.md` entry exists (`OverviewEntry`). `BootstrapTag` (`bootstrap`) marks the bootstrap issues; `Tree.BootstrapStart()` returns the first unresolved bootstrap-tagged leaf (the survey while it is open, then the area issues). `Tree.PlanBootstrap(actor, now)` returns the changes that create the structure on a progressively applied tree: the parent (kind manual, with one criterion), the survey child (kind research) with its requirement, context (the step-by-step survey procedure: read docs and code, write the map as findings, have the user review it, write `/overview.md` as a draft with `prep knowledge new`, create one child per area under the parent with the bootstrap tag, complete with `--docs /overview.md`) and criteria. Both issues start open so the user still owns the define step.
- `PlanKnowledge` refuses new entries other than `/overview.md` while not bootstrapped (`G_BOOTSTRAP`), naming the next bootstrap issue.
- Store (`internal/mdstore/store.go`): `Init` no longer writes the placeholder overview; it creates `.prep/knowledge/` with a `.gitkeep`.
- CLI ([CLI](/components/cli.md)): `prep init` applies `PlanBootstrap` after creating `.prep` unless `--no-bootstrap`; `prep knowledge bootstrap` applies it when the knowledge base is not bootstrapped and no unresolved bootstrap issue exists, otherwise reports what applies. `prep prime` leads with an alert while not bootstrapped (JSON: `bootstrap`), naming `prep guide <start>` or `prep knowledge bootstrap`.
- Guide: `Guide.Alerts` carries the same alert for every issue and is printed first.
- Tests: the CLI harness runs `prep init --no-bootstrap` and writes the overview with `prep knowledge new`, so existing tests keep a bootstrapped project; new tests cover init, the gate, the bootstrap command, prime and guide alerts, and that completing the survey with the overview bootstraps the project.
