Design: D1, D5, D7 on 01M46ARM9G3492V298TM82KD45. Port of the Claude Code panel ([Claude Code side panel](/components/claude-code-panel.md)): `plugins/claude-code/hooks/register.tsx` (activation, following, refresh, watch, commands), `panel.tsx` (drawing), `infer.ts`.

- **Pi APIs**: wide form `ctx.ui.custom(factory, { overlay: true, overlayOptions: () => ({ anchor: 'top-right', width: '35%', minWidth: 40, nonCapturing: true, visible: (w) => w >= threshold }), onHandle })`; keep the promise open while the pane lives and resolve through `done` on close. Narrow form `ctx.ui.setWidget('prep', factory, { placement: 'aboveEditor' })`; full view on demand as a capturing overlay. `visible` is checked every render, so one component pair switches on resize; the strip hides itself when the side pane is visible. Components from `@earendil-works/pi-tui` (`Text`, `Markdown` with `getMarkdownTheme()`, `Box`, `ScrollView`); width with `visibleWidth`/`truncateToWidth`; colors via `theme.fg(token)`; never cache themed strings outside `invalidate()`.
- **Threshold**: Claude Code seats its pane from 144 columns; start there, as a constant.
- **Following**: `pi.on('tool_result')` for `bash`/`powershell` (`event.input.command`, text of `event.content`), `edit`/`write` (`event.input.path`), skip `isError`; nested calls arrive the same way. Never return a value (the handler must not change results); wrap in try/catch.
- **Data**: run `prep` with `execFile` and `--json`; a sequence number drops stale refreshes. `prep watch` spawned at `session_start`, killed at `session_shutdown` (idempotent); restart on unexpected exit with backoff.
- **Opening**: Pi has no plugin userConfig; read the setting from the extension's own entry in Pi settings or `~/.config/prep/config.yaml`? Keep it in prep's user config (`internal/userconfig`, key like `pi.pane`) only if a Go change is wanted; otherwise a per-project open flag in a small JSON file under Pi's agent dir. Decide while implementing and record it.
- Guard all UI with `ctx.mode === 'tui'` (D6 tests run headless).
- **Tests**: view-model functions (issue JSON → lines) as unit tests at fixed widths; following through the SDK session with faux bash calls.
