Decided 2026-11-11 by the agent in a review of the usage follow-ups, the user having left open questions to it. Adds to the hand-off decision 01M72CVCP45FN7D515257JH6VE, which stays in force.

1. The report is a file. The brief names a report path and tells the implementer or checker to write the report there and to answer with one line. Reason: a subagent's final message lands in the orchestrator's context, and writing it to a file from there would cost output tokens in the large context, which is the cost the hand-off decision set out to avoid.
2. Brief and report have a default place per issue under `.prep/local/handoff`, shared by `prep brief <id> --out` and `prep handback <id>`, so neither needs a path. It is local to the machine and not versioned. The brief gives the report path as an absolute path; this is the one path under `.prep` a brief may name.
3. The brief for an issue that failed a check carries the failures: the newest "Check failed" entry of the work log is part of the brief, so the orchestrator restates nothing.
4. Decision bodies in a brief: full text for decisions linked to the issue itself, title and description for those from ancestors, from a scope or from a derived scope, with one bound on the whole section.
5. A decision in a report may carry a scope line; without one it is linked to the issue and gets its scope from the issue's changes (decision on scopes of the same day).
6. The commands ship first, then the trial with a small model on real issues, then the change to rules, skill and guide, as separate issues, so the guidance only changes after the report format has held.
