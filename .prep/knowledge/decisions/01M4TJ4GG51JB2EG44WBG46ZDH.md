In an initialized prep project, search for existing work before implementation. (1) Reuse a clear matching issue and follow its guide/lifecycle; (2) for unmatched small implementation, create an issue first; (3) for unmatched substantial implementation, create an issue first as well. Size is not the trigger. Honor explicit no-tracking/no-record-write instructions and keep incidental documentation within the existing task. Ordinary questions, exploration and planning do not automatically create issues. If an issue is named, inspect that issue and its current guide instead of filing another; ask when a reference is ambiguous. Search-before-create avoids duplicates, uniform tracking keeps knowledge and status in step, and explicit user scope prevents unwanted record changes. This replaces the natural-fix-no-issue assumption; update its assertions and add opt-out/read-only cases.
