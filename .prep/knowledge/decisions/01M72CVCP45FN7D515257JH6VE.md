Decided 2026-11-10 by the agent, the user having proposed the direction and left the open questions to it. Reason: the user orchestrates in one harness and implements in others, wants implementers (Pi in particular) as light as possible, and the daypack sessions showed the orchestrator writing every hand-off by hand (39 subagent prompts, 68 codex runs) while implementers spent 9.3% of their cost on requests that only ran prep (finding 01M72A9TBJ5JQXT2VGT15N2HW1).

The four questions:

1. Default or option: the brief is the default hand-off. The workflow rules tell an orchestrator to hand off with `prep brief`, not with "run prep guide <id>". `prep guide` stays for an agent working alone and for the orchestrator itself. Alternative rejected: keeping both as equal options, which leaves the choice to judgment again.
2. Checker: also prep-free. `prep brief <id> --check` gives the criteria, the Definition of Done and where the change is; the checker returns a verdict per criterion. Completion is the orchestrator's `prep handback`. Reason: the same lightness and the single writer; the separation of implementer and checker passes is kept.
3. Report: a fixed format that the binary parses (headed sections for summary, criteria, decisions, findings, problems). Reason: if the orchestrator had to read the report and write the records itself, the bookkeeping would move into its large context and the saving would be lost. A report the binary cannot parse changes nothing and says what is wrong. Risk: implementers that do not keep to the format; the brief ends with the format, and the first implementation is tried on real issues before the rules change.
4. Hooks inside implementers: unchanged. Where a harness runs prep's hooks in subagents they stay active; the record redirects protect `.prep` from an implementer that has no reason to touch it. Nothing is added to exempt implementers.

Scope: code and research issues that are ready. Decision and manual issues are not handed off this way.
