The Claude Code bridge now emits a model-named gap when usage has no non-zero input, output, cache-read or cache-write counts, including empty and missing usage objects. Event.Validate rejects request events with no non-zero tokens, context or cost, even when status is set; existing summary validation is unchanged. The bridge emits a summary marker with status entered on the first turn.step in each session and on each turn.complete entry, before calling downstream work. Summary markers avoid inventing requests or falsely marking healthy coverage as partial. Caught session.start, turn.start, turn.complete and session.end errors emit gap events with status/verb error, the lifecycle name as op and the error as target; failed delivery still uses the durable bridge-disabled gap. Existing session started, tool and hook events are unchanged. The plugin tests exercise empty/zero usage, all four usage counters, marker ordering and session-ID reset, and session-start/usage failures through the existing claude-code/testing setup. This updates the proposed fixes in finding 01M7Q90VEB8J1NZ9FSRGS1A7X2; no live cloud rerun was performed.
