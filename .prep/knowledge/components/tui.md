# TUI

Applies when changing or adding TUI screens. Looks come from the [TUI design system](/components/tui-design-system.md); screens own state and compose its components.

- **Entry**: `prep tui` (`internal/cli/tui.go`) needs a terminal and calls `tui.Run` with `Options{Load, Watch}`: the CLI's own loader and the `.prep` directory. `internal/tui` never imports the storage adapters ([Architecture](/components/architecture.md)).
- **Issue views** (`app.go`, `Model`): tabs are the saved views in config order (`domain.ViewNames`, from `Config.ViewOrder`), each with its count, queried with `domain.ParseFilter` and `Tree.Query` like `prep list`. The list pane shows `ui.ListRow` per issue (short ID = the last 6 characters of the ULID, its random part; any unique suffix resolves in the CLI; state, kind, progress, stale or blocked); the detail pane renders `detailMarkdown` (`detail.go`) with `ui.Markdown` into a Bubbles viewport, cached per issue, width and load generation. Markdown links show as text plus path.
- **Hierarchy**: tabs hold display rows, not bare IDs. Tree mode (default, `t` toggles flat) lays rows out with `Tree.WithAncestors` and `Tree.TreeOrder` like `prep list --tree`; ancestors that only give context are dimmed and not counted in the tab; they carry the same information as result rows (progress, notes, priority), all in the subtle tone. A per-tab scope stack focuses a parent (`→` on a parent, `←`/esc up): the view narrows to its subtree, the parent first, with a breadcrumb in the pane title. `p` jumps to the parent. The detail shows links by shape above the document (`relationBlock`, no label column): the ancestors as a breadcrumb (`↑ Release 0.1.0 › TUI …`), the children as a tree (`├─`/`└─`) under `Children` with the parent's progress, then `← needs` for dependencies (in the warning tone while unresolved) and `→ unblocks` for issues that depend on this one; each link uses the list's row grammar (`ui.LinkLine`: glyph, ID, progress or note, priority, title), children ordered by priority. The block shows up to `maxRelations` lines, then `… n more · o selects`. `o` enters link mode (`openLinks`, `linkKey`; 01M48KB2N0W7FZNTG77283QZJ8): each link line shows its key (`linkKeys`) and the selected one sits on the selection background; j/k or arrows move (wrapping like menus), enter or a link's key follows it (`o 3` still jumps), esc or o leave, other keys leave and act. `linkTargets` orders the links as drawn: the parent (the breadcrumb line stands for it), children, needs, unblocks, knowledge; the block scrolls (`… n above`) to keep the selection visible. Outside link mode the block looks as before; `p` jumps to the parent, backspace returns through a back stack. Tab never moves between links: it switches views in the list and the detail alike. Jumps select the issue in the current tab when it is a row there, else in the first view without flags, clearing its focus.
- **Tags** show as `#tag` after titles in list rows and under the meta line in the detail; the filter bar accepts `--tag`.
- **Priority** (01M4874AR04JFPZ5KYW0402JC1): `ui.PriorityMark` before titles in list rows (medium unmarked), `priority **<level>**` in the detail meta line; tabs and tree mode order by priority through `Query` and `TreeOrder`; the filter bar accepts `--priority`; action `i` (Set priority) opens the menu dialog with its own `heading` and the levels as entries (c, h, m, l; the current one marked) and writes a priority-only `PlanEdit`, also on resolved issues.
- **Filter bar**: `f` filters the tab with `prep list` flags and words, with a picker for flag values; see [TUI filter bar](/components/tui-filter.md).
- **Stale diff**: for a stale issue the detail starts with `staleDiff`: the kind change and a `ui.DiffLines` line diff of the newest baseline's requirement against the current body, rendered with `ui.Diff`.
- **Knowledge screen**: `b` opens the read-only knowledge base; see [TUI knowledge screen](/components/tui-knowledge.md).
- **Agent screen**: `w` opens what an agent is doing, live; `prep tui --agent` starts there; see [TUI Agent screen](/components/tui-agent.md).
- **Screens**: `c` shows the check screen (`ui.DiagnosticRow` per diagnostic, errors then warnings), `s` the settings (see Settings below); esc or the same key returns. `Options.Check` loads with knowledge drift (git, about 170 ms) and runs only when the check screen opens or reloads while open; the header shows the last counts. The CLI builds fresh stores per load because reloads and checks can run concurrently.
- **Editing and keys**: writes, the action and edit menus, dialogs, inline text editing, the keymap and the settings screen are in [TUI editing and keys](/components/tui-editing.md).
- **Layout**: `ui.Split(width, 0.55, 52, 40)` through `Model.split`; when both panes do not fit (below 92 columns) only the focused pane shows and enter/esc switch. `z` (01M4E6210TWXPM6DE6W4CP5W7G) toggles between that adaptive split and one pane at any width on every split screen (issues, knowledge, Agent); the choice is the user's `tui.layout` (`single`, unset meaning split) in the [user configuration](/components/setup.md), passed as `Options.Single` and saved through `Options.SaveLayout`, like mouse capture.
- **Keys** depend on the focused pane. Both: 1–9 switch tabs, a actions, e edit menu, i priority, n new issue, ? all keys, t tree/flat, p parent, c check, s settings, y copies the ID with OSC 52, r reloads, q quits. List: f filters. List: tab/shift+tab switch tabs; up/down, j/k, g/G, pgup/pgdn move; enter opens the detail; right/l focuses a parent or opens the detail; left/h/esc leave a focused parent. Detail: tab/shift+tab switch views as in the list, o goes to a linked issue, backspace goes back, esc/left return to the list, other keys scroll. The footer shows the essential keys of the current screen, a notice, or the last load error.
- **Live reload** (`internal/watch`, shared with `prep watch`): fsnotify on every directory under `.prep`, new directories added as they appear, debounced 150 ms, delivered as a `watch.Change` saying whether the project (`Tree`) or `.prep/local` (`Local`) changed, merged until read: a project change reloads the tree, a local change only re-reads the activity stream, so a busy agent never makes the TUI reparse every issue. `apply` keeps each tab's selection by issue ID; a load error keeps the last good tree and shows the error.
- **Tests** (`app_test.go`): fixtures are built through the domain and markdown store with a fixed clock and a seeded `rand.ChaCha8` as ID entropy (stable IDs); screen snapshots at 110×28 and 80×24 in `internal/tui/testdata`, tests for tabs, selection across reloads, detail content and load errors, dialogs over the screen and the settings screen (`dialog-*`, including the wizard's kind step and the keymap, and `settings-*` goldens at both sizes), the edit menu and keys, the create wizard and settings edits; the watcher is tested in `internal/watch`. `go test ./internal/tui/... -update` rewrites goldens.
- **Program** (Bubble Tea v2): `View` returns a `tea.View` (alt screen; mouse per [TUI mouse](/components/tui-mouse.md)); tests snapshot its `Content`.
 Startup assumes dark and asks the terminal in `Init`; the answer re-themes (`retheme`) without delaying startup. Pastes (`tea.PasteMsg`) go to the field taking text (`paste`). Viewports scroll vertically only (`newViewport`), so left and right keep their navigation meaning.
