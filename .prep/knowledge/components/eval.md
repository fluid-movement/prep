# Agent behavior tests (prep eval)

Applies when changing the agent behavior test suite or anything that runs agents against prep to measure them. Decided in 01M4QKTQVR3J6PJZAJM0MVWQR0 and its children. The idea: reliable tool use by agents is only provable by running agents, so the suite builds fake prep projects, runs a Claude Code session on a prompt in one of them, and checks that the expected tools were used and the expected outcome came to be. Deterministic wherever possible; an agent judge only for what cannot be checked mechanically. Results are pass rates over repeated runs, so the same suite compares variants of the hooks and skill, models (which is enough for which task) and, later, other harnesses.

Layout: code in `internal/eval/*`, content in `eval/` (`cases/<area>/*.yaml`, `fixtures/*.yaml`, `variants/<name>/variant.yaml`, `judge/calibration/*.yaml`, `results/` git-ignored, `baseline.json` once created). Commands: `prep eval run|list|doctor|report|compare|models|errors|check|judge-check|prune|clean` (`internal/cli/eval.go`, `eval_run.go`; `--dir` names the eval directory, default `./eval`). Needs a credential, because a private Claude config directory has no login: `just eval-login` once (runs `claude setup-token`, keeps the token in `~/.config/prep/eval-token`, mode 600), or `CLAUDE_CODE_OAUTH_TOKEN` / `ANTHROPIC_API_KEY` in the environment, which win (`env.AuthFromEnv`). Evals run locally only, using `just eval-smoke` or `just eval-full`.

- **Fixtures** (`fixture`): a YAML `Spec` (or `WorkspaceSpec` for several linked projects) is built by running the real prep binary as a subprocess with `--by fixture`, so a fixture is valid by construction and reaches issue states (open, defined, ready, in-progress, done, dropped) through the real transitions. Issues have aliases; `{{alias}}` and `{{project/alias}}` expand to IDs in bodies, contexts, criteria and knowledge. Determinism: `cli.Main` reads two test-only variables (`testSeams`), `PREP_TEST_NOW` (RFC3339 clock) and `PREP_TEST_SEED` (seed for the random bits of IDs); the builder advances the clock a second per call, so two builds are byte-identical. A workspace has its own HOME and registry (`XDG_STATE_HOME`) and builds projects in link order; the optional `repo` section makes a git repository with stub files (some executable) and fixed dates; `bootstrap: true` runs `prep init` with its bootstrap issues and leaves the knowledge base empty; `generate` adds synthetic issues and entries to reach a realistic size; knowledge entries take a `scope`. The builder clears its own focus at the end, so the agent's first briefing does not show setup as recent work. Queries (`Project.Query`) pass no `--by`, so they are not recorded in the activity stream.
- **Environment** (`env`): each run gets its own HOME, `CLAUDE_CONFIG_DIR`, registry and PATH with a pinned copy of the binary first; the harness environment is built from scratch (only auth, TERM, LANG, TMPDIR from the caller). `Leaks` compares what a session's init event reports (plugins, skills, memory paths, cwd) with what the variant provides; `Probe` runs one trivial session for it (`prep eval doctor`). The variant's plugin loads with `--plugin-dir`, never installed.
- **Transcript** (`transcript`, `transcript/claudecode`): `claude -p --output-format stream-json --verbose` is parsed into a harness-neutral `Transcript` (steps, prep commands parsed out of shell calls, meta, counts); another harness needs only an adapter. Unknown events are tolerated.
- **Cases** (`evalcase`): prompt, fixture (inline or by reference), expectations (`tools`, `outcome`, `rubric`), limits; loaded and validated completely (unknown keys, aliases, kinds). Assertion nodes keep their `{{aliases}}` until the fixture is built. Kinds register in `assert`: tools (`ran`, `not_ran`, `before`, `max_calls`, `no_errors`, `args`, `final_mentions`, `no_prep_files`, `any_of`; selectors can pick steps run by a subagent, which the stream marks with the spawning call) and outcome (`issue` incl. `stale`, `open_questions` and `state: a|b`, `unchanged`, `knowledge`, `check`, `claimed`, `repo`, `created` with bounds on new issues and entries); outcome checks read `assert.Snapshot`s taken through `prep ... --json` before and after the run and a `Diff`.
- **Runner** (`run`): builds the workspace, runs claude headless with the case's limits (`--max-turns`, `--max-budget-usd`, timeout with process-group kill), and returns a `Record` with a status (completed, timeout, budget, turns, error); a harness failure is an error status, never a failed assertion. `Release(pass)` keeps the workspace of a failing run.
- **Judge** (`judge`): one call per rubric item, pinned model, no tools, JSON verdict with evidence, one retry, errors never count as passes; `Calibrate` measures agreement with hand-labelled samples and marks results untrusted below a threshold (`prep eval judge-check`).
- **Matrix** (`matrix`): cells are case × variant × model, each run N times with bounded parallelism and a seeded order; a cell reduces to a pass rate with a Wilson interval, failed assertions, flakiness and cost; harness errors are excluded from the rate; optional sequential stop; `--max-usd` stops cleanly. `Estimator` predicts cost from earlier runs.
- **Results** (`results`): `eval/results/<run-id>/` with `matrix.json`, `cells.json` and per-run files; `Report`, `Compare` (a difference counts only when the intervals do not overlap), baselines (`prep eval check`).
- **Variants** (`variant`): `current` (the shipped plugin), `none`, or a directory with a `variant.yaml` (base, replace, add, remove, append_system_prompt); materialized with a content hash recorded in results.
- **Models** (`models`): `prep eval models <run>...` pools cases per area (`report` and `models` take several run IDs and pool the runs of each cell, `results.Merge`, so models can be run in separate sessions and topped up later) and names the cheapest sufficient model by cost per passing run (default: rate ≥ 90% and interval lower bound ≥ 80%), says "not enough data" with the number of runs needed, lists what cheaper models get wrong, and warns when a model alias resolved to different ids.
- **What the cases ask**: see [Agent behavior test cases](/components/eval-cases.md).
- **Not covered yet**: other harnesses (a follow-up issue in release 0.4.0), and the first live baseline run (it needs a token).

Fixture completion setup records explicit manual observations for each bound requirement before completing an issue. It also records a matching no-impact knowledge review report, so bound-contract completion setup satisfies the completion contract. These are reports about fixture construction, not independently verified implementation checks; live agent evaluation must supply its own reports. See [Completion policy](/features/completion-policy.md).

Kept run environments (workspace, private Claude config and agent edits) live outside the checkout under the system temporary directory in `prep-eval-work-*`. `prep eval prune --keep N` removes the environments recorded in the results it deletes, including passing runs retained with `--keep`, and removes empty workspace parents. The newest N stored results and their environments remain available. `prep eval clean` removes all `prep-eval-work-*` directories older than 24 hours, including leftovers whose results are already gone; `prep eval clean --all` includes recent directories too. `clean` searches the current system temporary directory (`TMPDIR` where set); stop active eval runs before using `clean --all` or cleaning a run lasting over a day. Cleaning workspaces leaves stored transcripts and results in place, but their workspace paths will no longer exist.
